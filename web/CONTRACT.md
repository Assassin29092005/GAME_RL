# HellwalkerRL telemetry contract (v1)

The game, the website, the mock server and the Firestore rules all follow this file. Change it first, then them.

**Purpose.** Research data for the HellwalkerRL paper: how players fare against the RL keeper and how they feel about it.
No accounts and no login window: each install signs in to Firebase **anonymously** (invisible), gets a random user id
(`uid`), and sends one record per duel. Sharing is on for everyone (owner's decision); the game shows one line saying
anonymous gameplay stats are sent for research, and the website lets a player **reset** everything recorded about them.

## Services and endpoints (Firebase, plain REST — no SDK in the game or the site)

| base (real) | base (mock, `http://127.0.0.1:8099`) | used for |
|---|---|---|
| `https://identitytoolkit.googleapis.com/v1` | `{mock}/identitytoolkit/v1` | `POST /accounts:signUp?key={apiKey}` body `{"returnSecureToken":true}` → `{idToken, refreshToken, localId, expiresIn}` |
| `https://securetoken.googleapis.com/v1` | `{mock}/securetoken/v1` | `POST /token?key={apiKey}` form `grant_type=refresh_token&refresh_token=…` → `{id_token, refresh_token, user_id, expires_in}` |
| `https://firestore.googleapis.com/v1/projects/{projectId}/databases/(default)/documents` | `{mock}/firestore/v1/projects/{projectId}/databases/(default)/documents` | documents (below), `Authorization: Bearer {idToken}` on writes and on owner-only reads |

Firestore REST calls used: `POST …/documents:commit`, `GET …/documents/{path}`, `PATCH …/documents/{path}?updateMask.fieldPaths=…`,
`DELETE …/documents/{path}`, `POST …/documents:runQuery`, `GET …/documents/{collection}?pageSize=&pageToken=` (list).
Values use Firestore's typed JSON (`integerValue` as a string, `doubleValue`, `stringValue`, `booleanValue`,
`timestampValue` RFC 3339, `mapValue.fields`, `arrayValue.values`, `nullValue`). Firestore forbids arrays of arrays.

Configuration: the game reads `Config/DefaultGame.ini` `[HWTelemetry]` (`bEnabled`, `ApiKey`, `ProjectId`, `SiteUrl`); the
site reads `web/config.js`. Empty `ApiKey`/`ProjectId` = telemetry off (the game stays silent; the site shows demo
data with a banner). `-HWTelemetryEndpoint=<url>` (game) / `?mock=<url>` (site) route every base above to the mock.
The Firebase web API key is not a secret (security is the rules); restrict it to the Identity Toolkit, Token Service
(securetoken) and Cloud Firestore APIs.

## Identity

- First launch with telemetry configured: `accounts:signUp` → keep `localId` (= `uid`) and `refreshToken` in the
  game's own save slot (`HWTelemetry`). Refresh the `idToken` with `securetoken` when it is older than 50 minutes.
- Then create `players/{uid}` once (commit with `currentDocument.exists=false`): nickname `"<Adjective> <Noun> <4 digits>"`
  generated by the game (e.g. `Ashen Wanderer 4821`), `createdAt` = server time, all totals 0.
- **Linking a browser** ("Open my stats page" in the game): the game opens `{SiteUrl}/#/me?t={refreshToken}`. The site
  exchanges the token at `securetoken`, keeps `{uid, refreshToken}` in `localStorage`, and immediately removes the token
  from the address bar (`history.replaceState`). Only a linked browser can reset, edit the nickname or answer the survey.
  Anyone can view any profile at `#/p/{uid}` (anonymous numbers only).

## Documents

### `fights/{fightId}` — one per finished duel (immutable)

`fightId` = 32 lowercase hex chars generated by the game (so a retried upload is idempotent: the commit uses
`currentDocument.exists=false`). A retry of a fight that already arrived is refused — as ALREADY_EXISTS, or as
PERMISSION_DENIED when the rules see an update of an immutable fight; on any 400/403 the game reads `fights/{id}`
(public) and counts an existing document as delivered. Queued bodies carry `{uid}` in place of the player id, filled at
send time.

| field | type | meaning |
|---|---|---|
| `v` | int | 1 |
| `player` | string | uid (must equal the signed-in uid) |
| `at` | timestamp | server time (transform `setToServerValue: REQUEST_TIME`) |
| `clientTime` | timestamp | the game's clock |
| `session` | string | random per game launch (32 hex) |
| `fightInSession` | int | 1, 2, … within this launch |
| `gameVersion` | string | e.g. `"1.2.0"` |
| `mode` | string | `"openworld"` or `"arena"` |
| `playMode` | string | `"pathbreaker"`, `"hellwalker"`, `"66days"` (open world) or `"arena"` |
| `brain` | string | `"rl"` (the RL keeper) or `"script"` (Pathbreaker) |
| `keeper` | int | 0 Warden, 1 Sage, 2 Returned |
| `keeperName` | string | the boss title shown to the player |
| `difficulty` | string | `Easy`, `Normal`, `Hard`, `Hellwalker`, `Adaptive` |
| `skill` | double | the keeper's skill this fight (0..1) |
| `adaptive` | bool | Adaptive difficulty |
| `result` | string | `"win"` (player won), `"loss"`, `"timeout"`, `"quit"` |
| `seconds` | double | fight length |
| `playerHealth`, `keeperHealth` | double | fraction of health left (0..1) |
| `dmgDealt`, `dmgTaken` | double | damage the player dealt / took |
| `playerSwings`, `playerHits` | int | player attacks committed / that hit |
| `keeperSwings`, `keeperHits` | int | keeper attacks / that hit the player |
| `keeperBlocked`, `keeperParried`, `keeperWhiffed` | int | keeper attacks the player blocked / **parried** / dodged or that missed |
| `parryAttempts` | int | parry presses by the player |
| `dodges` | int | ghoststeps by the player |
| `guardBreaks` | int | times the player's guard broke |
| `keeperExposed` | int | times the keeper's guard broke |
| `readsLanded` | int | READ banners (the keeper hit the answer it predicted, confidently) |
| `predictions`, `predictionsCorrect`, `confident`, `confidentCorrect` | int | the keeper's read head this fight (FRLNotebook); 0 for the script |
| `expected` | array of 8 maps `{attack: string, answer: string, p: double}` | what the keeper expects you to do against each of its 8 attacks, after this fight (empty array for the script) |
| `answers` | map `{fast|heavy|feint|killer: {<answer>: int}}` | what the player actually did against each kind of keeper swing this fight; answers `parry, block, stepL, stepR, stepB, stepF, attack, none` |

### `players/{uid}` — one per install (public read, owner write)

| field | type | meaning |
|---|---|---|
| `v` | int | 1 |
| `nickname` | string | 1..24 printable chars |
| `createdAt` | timestamp | set once |
| `lastSeen` | timestamp | server time of the last upload |
| `gameVersion`, `difficulty` | string | from the last upload |
| `totals` | map | `fights, wins, losses, timeouts, seconds(double), dmgDealt(double), dmgTaken(double), playerSwings, playerHits, keeperSwings, keeperHits, keeperBlocked, keeperParried, keeperWhiffed, parryAttempts, dodges, readsLanded, predictions, predictionsCorrect, confident, confidentCorrect` (ints unless marked) |
| `keepers` | map | `warden|sage|returned: {fights, wins}` |
| `answers` | map | cumulative, same shape as the fight's `answers` |
| `expected` | array | the latest fight's `expected` |
| `survey` | map (optional) | `{feltRead, fair, difficulty, fun, playAgain}` each int 1..5, `noticedAdapting` bool, `at` timestamp — Likert answers are public and anonymous |
| `resets` | int | how many times the player reset |
| `resetAt` | timestamp or null | the last reset |

Per fight the game sends ONE `documents:commit` with two writes: (1) create `fights/{fightId}`; (2) update
`players/{uid}` with `updateMask` = `v, gameVersion, difficulty, expected`, plus `updateTransforms`: `lastSeen` ←
REQUEST_TIME and `increment` on every `totals.*`, `keepers.<name>.fights|wins` and `answers.<class>.<answer>` that changed.
Uploads that fail (offline) are queued in the save slot and retried at the next fight and at start-up. Never uploaded:
fights played by the autoplay bot, parity runs, fights touched by hw.Kill / hw.InjectParry / hw.Hold, and scripted
launches (-unattended, -HWExec) — unless a mock endpoint and -HWTelemetryAllowAutoplay are both given (tests, which also
use their own save slot).

### `surveys/{uid}` — private (owner only)

`{v:1, comment: string ≤ 500 chars, at: timestamp}` — the free-text part of the survey (the researcher reads it in the
Firebase console). The Likert part lives in `players/{uid}.survey`.

## Reset ("forget everything it learned about me") — website, linked browser only

1. `runQuery` `fights` where `player == uid` (page through), `DELETE` each (or commits of ≤ 500 deletes).
2. Update `players/{uid}`: totals, keepers and answers back to 0, `expected` = [], `resets` + 1, `resetAt` = REQUEST_TIME
   (nickname, `createdAt` and the survey stay).
The game keeps no totals of its own (the server increments). Once per launch, before uploading, it reads its
`players/{uid}.resetAt` and drops queued fights recorded before it. The keeper's in-session memory is dropped when the
game quits, as always.

## Rules (summary — `web/firebase/firestore.rules` is the source)

- `players/{uid}`: read public; create/update only by `uid` itself, schema-checked (types, ranges, counts ≥ 0,
  `createdAt` immutable after create); no delete.
- `fights/{id}`: read public; create only with `player == request.auth.uid` and a valid schema; never updated; delete
  only by its owner (reset).
- `surveys/{uid}`: read/write only by `uid`.
- Everything else denied.
Indexes: `fights` (`player` ASC, `at` DESC) for the profile's recent fights.
